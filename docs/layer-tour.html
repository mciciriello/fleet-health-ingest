Wireframe · operator tour · not a running app

You open Layer when you do not want to SSH.

This is not a custom website we will paint from scratch. The thing you look at is Grafana, dashboard Layer. Hosts (navis) POST a tiny health sample. You glance. Green, leave it. Red, go look. Same instinct as a Proxmox panel: one place, fleet first, then the sick box.

1. Why you would want this

You already know the feeling: a handful of Linux boxes, and the only way to know they are unhappy is to log in. That does not scale past “I remember to check.” Layer is the check, done for you.

the job in one sentence

Before: SSH to navi-01, top, SSH to navi-02, repeat. Hope you noticed the one that is swapping.

After: Open Layer. Three navis reported in the last few minutes. Two are fine. One is not. You go to that one.

If a client asked for “a monitoring panel for Proxmox,” you would sketch nodes, red/green, then a drill-down. This is that sketch, for generic host health, not a hypervisor.
End user You. The person who owns the boxes. Not a customer portal. Not a vendor console. A lab panel you would actually leave open on a spare screen.

6. How a host talks in (not a GUI)

There is no pretty “agent settings” page in this lab. A navi (or you, with curl) POSTs JSON. If that stops, Layer goes quiet for that name. Quiet is the bug.

POST /ingest · the only write path
{
  "host": "navi-01",
  "cpu_pct": 12.4,
  "mem_pct": 41.0,
  "ok": true
}
Why this is enough Four fields. You can cron it, you can fake it with ./scripts/post-sample.sh. The UX promise is on the read side (Layer), not a second app to configure hosts.

7. Lab today vs this picture

Believe the destination. Do not pretend Grafana already looks like screen 2. Cloud later does not change the UX. It changes where Layer is reachable from.
